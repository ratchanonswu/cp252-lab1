# cp252-lab1
## Functional Requirement 
1: ผู้ใช้สามารถสร้างบัญชี ลงทะเบียน และเข้าสู่ระบบด้วยอีเมลหรือเบอร์โทรศัพท์  
2: การค้นหาห้างสรรพสินค้า ผู้ใช้สามารถค้นหาห้างสรรพสินค้าตามชื่อ สถานที่ หรือพื้นที่ใกล้เคียง  
3: ระบบแสดงจำนวนที่จอดรถว่างแบบ real-time ของแต่ละห้างสรรพสินค้า พร้อมแยกตามชั้นและโซน  
4: ผู้ใช้สามารถจองที่จอดรถล่วงหน้าโดยระบุวันที่ เวลา และระยะเวลาที่ต้องการจอด พร้อมรับหมายเลขที่จอดเฉพาะ  
5: ผู้ใช้สามารถยกเลิกการจองที่จอดรถก่อนถึงเวลาที่กำหนด ระบบจะคืนสถานะที่จอดเป็นว่างอัตโนมัติ  
6: ระบบหมดอายุการจอง เมื่อหมดเวลาการจองที่กำหนดไว้ ระบบจะปรับสถานะที่จอดเป็นว่างโดยอัตโนมัติ  
7: การคำนวณค่าธรรมเนียม ระบบคำนวณค่าจอดรถตามระยะเวลาที่จอดจริง โดยมีอัตราค่าบริการตามที่ห้างกำหนด (เช่น ชั่วโมงแรก 20 บาท ชั่วโมงต่อไป 10 บาท)  
8: การนับจำนวนรถในลานจอด ระบบติดตามและแสดงจำนวนรถที่จอดอยู่ทั้งหมดในห้างแต่ละแห่ง แยกตามชั้นและโซน  
9: การจัดการที่จอดรถสำหรับห้างเจ้าของห้างสรรพสินค้าสามารถเพิ่ม ลด หรือแก้ไขจำนวนที่จอดรถ กำหนดอัตราค่าบริการ และจัดการโซนพิเศษ (เช่น ที่จอดคนพิการ)  
10: ประวัติการใช้งานและการชำระเงิน ผู้ใช้สามารถดูประวัติการจอดรถ การจอง และชำระค่าบริการผ่านแอปพลิเคชัน (QR Code, บัตรเครดิต)  
## Non-functional Requirement
1: ระบบต้องมีประสิทธิภาพ ระบบต้องแสดงข้อมูลที่จอดรถว่างแบบ real-time โดยมีความล่าช้าไม่เกิน 2 วินาที และรองรับผู้ใช้พร้อมกันได้อย่างน้อย 10,000 คน  
2: ระบบต้องสามารถใช้งานได้ตลอด 24/7 โดยมี uptime ไม่ต่ำกว่า 99.5% ต่อเดือน  
3: Security ข้อมูลผู้ใช้และการชำระเงินต้องได้รับการเข้ารหัส ป้องกันการเข้าถึงโดยไม่ได้รับอนุญาต และปฏิบัติตามมาตรฐาน PDPA  
4: ระบบต้องสามารถรองรับการเพิ่มห้างสรรพสินค้าและจำนวนที่จอดรถได้โดยไม่กระทบต่อประสิทธิภาพ  
5: แอปพลิเคชันต้องมี UI/UX ที่ใช้งานง่าย เข้าใจง่าย รองรับทั้งภาษาไทยและอังกฤษ และเข้าถึงได้สำหรับผู้พิการ  

#TOR Requirement
## Front-End Requirements
1.การจัดการบัญชีผู้ใช้ หน้า Login/Register ต้องรองรับการเข้าสู่ระบบด้วยอีเมลหรือเบอร์โทรศัพท์ มี form ที่ชัดเจน และรับบ้านแบบ single-sign-on เเละ forgot password  
2.หน้าค้นหาห้างสรรพสินค้าUI ต้องมี search bar ที่ค้นหาได้ตามชื่อ สถานที่ หรือ geolocation ใกล้เคียง พร้อม filter เเละ sort option มี map view หรือ list view ให้ผู้ใช้เลือก  
3.การแสดงข้อมูลที่จอดรถ จะต้องมีข้อมูล real-time ของแต่ละห้างแยกตามชั้นและโซน ใช้ visual คอยนำทางเช่น สีเพื่อบอกว่า วันที่ เลยต้องมี progress bar หรือ countdown ของการจอง  
4.หน้าจอง/ยกเลิกจอง ต้องมี date/time  ที่ user-friendly รับ input ระยะเวลา แสดง preview ค่าธรรมเนียม ก่อนยืนยัน พร้อม confirmation flow ที่ชัดเจน  
5.การชำระเงิน UI สำหรับเลือกวิธีจ่าย (QR Code, บัตรเครดิต) ต้องมี secure payment form พร้อม loading state และ success/error feedback  
6.ประวัติการใช้งาน หน้า history ที่แสดงการจอง, การชำระเงิน แบบ list พร้อม filter ตามวันที่ เรียง format ที่อ่านง่าย  
7.Accessibility & i18n ทั้ง UI ต้องรองรับ ภาษาไทย/อังกฤษ , เข้าถึงได้สำหรับผู้พิการ มี screen reader support  

## Back-End Requirements
1.Authentication & AuthorizationAPI จัดการ user registration, login ด้วย email/phone, session/token management, และ role-based access (ผู้ใช้ vs เจ้าของห้าง)  
2.ระบบค้นหาห้างSearch API รับ query ตามชื่อ, สถานที่ หรือ coordinates (geolocation) พร้อม pagination  
3.Real-Time Parking Status ต้อง maintain ข้อมูลที่จอดว่า/เต็มแบบ real-time ความล่าช้าไม่เกิน 2 วินาที  
4.Booking & Cancellation LogicAPI จัดการ CRUD ของการจอง ต้องมี concurrency control เพื่อป้องกันการจอง slot เดียวกันพร้อมกัน พร้อม logic หมดอายุเมื่อเวลาจบ  
5.การคำนวณค่าธรรมเนียม Business logic คำนวณค่าจอดตาม rate ของแต่ละห้าง (เช่น ชั่วโมงแรก 20 บาท, ต่อไป 10 บาท)  
6.Payment Processing Integration กับ payment gateway รับ QR Code หรือ card จัดการ transaction, refund หากยกเลิก พร้อม logging ทุก transaction    
7.การจัดการ parking สำหรับเจ้าของห้าง Admin API สำหรับ CRUD ที่จอดรถ, กำหนด rate, จัดการ zone พิเศษ (เช่น คนพิการ)  
8.ประวัติ & Reporting API ดึงข้อมูล history ผู้ใช้ พร้อม filter, รวมถึง analytics สำหรับเจ้าของห้าง  
9.Security & Compliance ต้อง encrypt ข้อมูลผู้ใช้และ payment data (TLS, encryption at rest), ปฏิบัติตาม PDPA, พร้อม rate limiting
